# Agent Onboarding & Self-Extension Guide

Welcome, Agent! You are working in the **ClearCutt Hardened Fleets** repository. 

To ensure you can operate here with maximum efficiency, zero regressions, and full synchronization with other AI tools, this repository implements a **Unified, Harness-Agnostic Agent DX & Memory System**.

Before starting any task or writing any code, please review this guide.

---

## 1. The Core Rules of Engagement

Every agent working in this repository MUST adhere to the following contract:

1. **Short-Term Context RAM (`.agent/active_context.md`):**
   * **At the start of your turn:** You MUST read `.agent/active_context.md` to restore the active state, goals, recent errors, and work progress.
   * **During your turn:** Update this file as you complete tasks.
   * **At the end of your turn:** You MUST write your current status, modified files, active blockages/test failures, and next steps into `.agent/active_context.md` so that the next agent can seamlessly resume your work.

2. **Long-Term Lessons ROM (`.agent/lessons_learned.md`):**
   * **Before making changes:** Read `.agent/lessons_learned.md` to check for known anti-patterns, environment bugs, and design constraints specific to this monorepo.
   * **Self-Improving Memory:** If you struggle with a bug for more than two turn cycles, or if you discover a subtle architectural constraint, you MUST write down a new lesson in `.agent/lessons_learned.md` to ensure future agents do not repeat the mistake.

3. **No Direct Config Edits:**
   * Never modify `.cursorrules`, `.claudeprompt`, `.windsurfrules`, `.github/copilot-instructions.md`, or `.vscode/tasks.json` directly.
   * Instead, modify the centralized source files in `.agent/` and compile them using `make agent-sync` (which runs `bash .agent/sync.sh`).

## 3. How to Self-Bootstrap / Extend for a New Harness

If you are using an AI harness that is **not** currently generated by `.agent/sync.sh` (for example, Cody, Aider, or a custom system):

### Step A: Locate your harness configuration file
Identify the file name and directory structure your AI harness uses to read project instructions (e.g., `.codyrules`, `.aider.conf.yml`, or similar).

### Step B: Modify `.agent/sync.sh`
Open `.agent/sync.sh` and locate the compilation block. Add a new compilation target block to generate your config file. For example:

```bash
# Compile My Custom Harness Rules
echo "==> Compiling .mycustomrules..."
cat << 'EOF' > .mycustomrules
# Custom Harness Header
EOF
cat .agent/instructions.md >> .mycustomrules
cat .agent/architecture.md >> .mycustomrules
cat .agent/lessons_learned.md >> .mycustomrules
```

### Step C: Compile and Commit
1. Run `make agent-sync` (or `bash .agent/sync.sh`) to generate your native configuration.
2. Verify that your harness now detects and respects the generated instructions.
3. Commit the updated `.agent/sync.sh` and add your generated configuration file to the `.gitignore` if it contains absolute paths or local state, or commit it if it is safe.
